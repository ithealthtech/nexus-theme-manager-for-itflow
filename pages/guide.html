Before installation

Installation

Recommended installer

Run from SSH as an operator with the required privileges. Replace the example root with the real ITFlow document root.

curl --fail --location --remote-name \
  https://raw.githubusercontent.com/ithealthtech/nexus-theme-manager-for-itflow/main/install-latest.sh

chmod +x install-latest.sh
sudo ./install-latest.sh --root /var/www/itflow.example.com

The installer resolves the latest published release, downloads its versioned ZIP and adjacent checksum, verifies the archive, extracts under /opt, checks the ITFlow baseline, installs and verifies Nexus, and configures the protected GUI updater.

Custom state directory

If the default protected state location is unsuitable, choose a local directory outside the document root and pass it consistently for every later lifecycle command.

sudo ./install-latest.sh \
  --root /var/www/itflow.example.com \
  --state-root /srv/secure/nexus-theme-state

Manual release installation

Use the versioned ZIP and checksum from the latest release. GitHub's automatically generated source archive is not the tested installation artifact.

sha256sum --check Nexus-Theme-Manager-for-ITFlow-3.9.1.zip.sha256.txt
sudo unzip Nexus-Theme-Manager-for-ITFlow-3.9.1.zip -d /opt
cd /opt/Nexus-Theme-Manager-for-ITFlow-3.9.1

sudo php manager.php doctor --root /var/www/itflow.example.com
sudo php manager.php install --root /var/www/itflow.example.com --yes
sudo php updater.php install-service --root /var/www/itflow.example.com
sudo php manager.php verify --root /var/www/itflow.example.com

Verification

Acceptance checklist

  1. Verify lifecycle stateRun status and verify. Both must report a healthy enabled installation.
  2. Open Theme StudioSign in as an administrator and open Administration → NEXUS → Theme Manager.
  3. Confirm updater readinessOpen Updates & System and confirm the protected updater reports Ready.
  4. Test authenticationCheck password login, reset, MFA, role selection, remember-me, and Entra paths used by the deployment.
  5. Test customer workflowsOpen the portal, list tickets, create a request, view a conversation, and check permission-controlled navigation.
  6. Test operationsInspect ticket queues, client context, administration pages, modals, tables, and configured integrations.
  7. Test responsive and printCheck phone navigation, horizontal table containment, guest invoice, and print/PDF output.
  8. Pin known goodAfter the initial design is published, pin its revision for recovery.

First configuration

Build a first design safely

i

Draft is private; published is live. Editing a field does not change user-facing pages. Save the draft, inspect regenerated previews and quality results, then publish only when ready.

  1. Set display name, logo alt text, tagline, and approved light/dark logos in Branding.
  2. Select the closest built-in palette in Colors, then make restrained adjustments.
  3. Keep global Layout defaults until the basic visual language is stable.
  4. Select Save draft.
  5. Review all eight surfaces at laptop, tablet, phone, and one custom width.
  6. Resolve important Design quality findings.
  7. Compare unpublished values with live values.
  8. Select Publish draft and use a meaningful revision name.
  9. Pin the accepted revision under Presets & schedule.

Discard draft removes unpublished changes only. Applying a preset, restoring a revision, importing a workspace, loading defaults, or applying quality fixes changes the draft and never publishes by itself.

Reference

Theme Studio workspaces

Branding

Manage display name, accessible logo text, tagline, browser title, light/dark logos, favicon, authentication artwork, surface visibility, sizing, alignment, crop and resize settings. Asset health reports dimensions, size, animation, frame rate, format companions, and warnings.

Colors

Begin with Aurora, Ocean, Emerald, Ember, or Slate. Adjust six-digit hex values for accent, gradient, shell, page, card, text, and other surfaces. Use the live contrast warning, then run the complete quality audit after saving.

Layout and surface profiles

Control corners, content density, menu density, sidebar width, header treatment, active navigation, compact labels, and interface scale. Enable overrides only where technician, client, authentication, guest, or print surfaces need to diverge from global settings.

Navigation builder

Reorder approved destinations, change labels and icons, set administrator/technician visibility, and independently control desktop and mobile presentation. Hiding a link is not authorization; ITFlow permission checks remain authoritative.

Automatic dark mode

Follow system preference, force light/dark, schedule a range using server-local time, or allow user selection. A saved user choice takes priority when user selection is allowed. Configure an independent dark palette and appropriate logos.

Design quality

Audit the saved draft at a 390px phone width. Findings name the surface and link to the responsible setting. Automatic fixes are allow-listed and remain unpublished until reviewed and published.

Motion and content

Choose subtle, fluid, or snappy UI motion while respecting reduced-motion preferences. Configure presentation-only authentication and portal copy without changing business logic.

Presets, revisions, and schedule

Compare draft to live, retain up to 50 revisions, pin known-good versions, restore into a draft, manage up to 20 reusable presets, import/export presets, and schedule whole-theme activation or pause.

Updates and system

Check and install verified releases, inspect update stages and rollback status, run health checks, restore known-good, emergency-disable, export/import workspace settings, download sanitized diagnostics, or load defaults into a draft.

Playbooks

Common daily workflows

Change a logo

  1. Open Branding and enter useful alt text.
  2. Upload approved light/dark assets and adjust size/alignment.
  3. Save the draft.
  4. Review every relevant surface in light, dark, desktop, and phone views.
  5. Resolve asset and quality warnings.
  6. Publish with a named revision.

Change colors

  1. Select the closest built-in palette.
  2. Adjust individual colors and watch contrast.
  3. Save the draft.
  4. Review both light and dark modes across surface profiles.
  5. Run Design quality and publish only after acceptance.

Undo a published design

  1. Open Presets & schedule.
  2. Compare the target revision with live.
  3. Select Restore to load it into the draft.
  4. Review the restored draft.
  5. Publish it as a new named revision.

Move a design between installations

  1. Export the workspace from Updates & system.
  2. Review the JSON and transfer it using an approved method.
  3. Import it to the destination draft.
  4. Uploaded asset references remain destination-specific unless managed separately.
  5. Review previews and publish deliberately.

Nexus releases

Update Nexus

From Theme Studio

Open Updates & System, select Check for updates, review the offered release, then install. Theme Studio queues only allow-listed operations. The root-owned service downloads the fixed repository release, verifies checksums and the package manifest, stages the package, protects the current version, activates, runs health checks, and restores the previous release if activation fails.

From SSH

cd /tmp
curl --fail --location --output install-latest.sh \
  https://raw.githubusercontent.com/ithealthtech/nexus-theme-manager-for-itflow/main/install-latest.sh
chmod +x install-latest.sh
sudo ./install-latest.sh --root /var/www/itflow.example.com

The installer installs when unmanaged, upgrades when newer, preserves enabled/disabled state, verifies the replacement, restores the previous package after activation failure, and reports when no update is needed. It refuses downgrades, invalid tags, bad checksums, incompatible ITFlow, mismatched state, and a missing current package.

Rollback

Pause, disable, or remove Nexus

ActionUse whenWhat remains
Pause themeTemporarily remove presentation customizationsSettings, drafts, revisions, and package
Emergency disableNative administrator presentation is urgently neededSettings/history for later recovery
Restore known-goodA published configuration is unhealthyA safety snapshot plus restored pinned/newest revision
Lifecycle disableRestore exact upstream templates or prepare for ITFlow updateManager state and backups
UninstallRemove the package-managed themeArchived recovery state by default
sudo php manager.php status --root /var/www/itflow.example.com
sudo php manager.php disable --root /var/www/itflow.example.com --yes
sudo php manager.php verify --root /var/www/itflow.example.com
sudo php manager.php enable --root /var/www/itflow.example.com --yes
sudo php manager.php verify --root /var/www/itflow.example.com
sudo ./uninstall.sh --root /var/www/itflow.example.com --yes

Nexus refuses to overwrite a managed file that changed after installation. Preserve and investigate reported drift instead of bypassing verification.

Compatibility

Update ITFlow safely

!

Do not run the ITFlow updater over an enabled Nexus payload. ITFlow has no native theme-hook system, so Nexus only claims compatibility with templates it has tested.

  1. Record and verifyCapture Nexus status and complete verification.
  2. Disable or uninstall NexusRestore the exact supported upstream templates before the ITFlow update.
  3. Update ITFlowComplete upstream migrations, checks, and application acceptance.
  4. Obtain a compatible Nexus releaseIts table and manifest must explicitly name the new ITFlow revision.
  5. Run doctor, install, and testProceed only after the exact compatibility preflight succeeds.
