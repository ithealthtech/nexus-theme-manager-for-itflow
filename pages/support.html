Troubleshooting and recovery

Start read-only. Preserve evidence. Recover deliberately.

Search common symptoms, understand safety refusals, and choose the smallest recovery action that restores service without discarding state.

First

Inspect status

See installed mode, package details, and managed-file conflicts without changing files.

sudo php manager.php status \
  --root /var/www/itflow.example.com
Second

Verify integrity

Check package hashes, active files, and PHP syntax before deciding on recovery.

sudo php manager.php verify \
  --root /var/www/itflow.example.com
Before sharing

Sanitize diagnostics

Use the Theme Studio diagnostics bundle. Never publish config files, credentials, databases, customer records, protected state, or private screenshots.

Symptom finder

Search troubleshooting

Type a command, message fragment, or visible symptom.

My draft changes are not visible
  • Select Save draft after editing so previews regenerate from validated settings.
  • Select Publish draft only after review if users should see the change.
  • Confirm Nexus is Active, not paused or emergency-disabled.
  • For logos, check the target surface switch and correct light/dark asset.
The preview did not update while I typed

Expected behavior: unsaved form values are not treated as a trustworthy preview. Save the draft to validate inputs and regenerate all previews.

A desktop or mobile navigation item disappeared

Open Layout → Navigation builder. Desktop and mobile lists are independent. Confirm Show is enabled and the current role is selected. Presentation visibility never replaces ITFlow authorization.

Dark mode uses an unexpected palette or schedule

If user selection is allowed, a saved user choice overrides the configured default. Scheduled mode uses server-local time. Confirm dark-from/light-from values and inspect the independent dark palette and logo selection.

Theme appears unchanged after a successful install or enable

Gracefully reload the actual PHP/web service to clear opcode caches, then hard-refresh a private browser window. Confirm that lifecycle status is enabled and Theme Studio presentation is active.

Compatibility check failed and no files were changed

The ITFlow revision, required template, or local template hash does not match the release manifest. Preserve local changes, confirm the exact ITFlow commit, and obtain a Nexus release explicitly built for that revision. Never force the install.

Package integrity or checksum verification failed

Stop. Remove only the suspect extracted/downloaded copy, obtain the versioned ZIP and checksum again from the official release, verify the outer archive, and extract a fresh package. Do not repair files inside an unverified archive.

Verification says a managed file changed after installation

Nexus has detected drift and refuses to overwrite it. Copy the changed file to an approved evidence location, identify whether it came from an ITFlow update, emergency patch, or manual edit, and restore a known state deliberately. Do not alter recorded hashes.

An original file changed while Nexus was disabled

Do not enable the old payload. The ITFlow instance likely changed while upstream templates were active. Complete ITFlow acceptance, then obtain a Nexus release compatible with the new revision.

Theme Studio says the updater requires setup

Run the exact one-time root command shown in Updates & System through SSH. Theme Studio never receives general shell access. Return to Theme Studio and select Check for updates.

An update failed or shows rollback details

Read the updater stage and bounded failure information. Confirm whether the previous package was restored and health-verified. Use Retry only for the same approved operation when offered. If manual attention is reported, preserve the diagnostics bundle and current package/state before changing anything.

Permission denied under the protected state directory

Use the expected approved root/sudo workflow, or choose a protected custom state root during initial installation. When a custom state root exists, pass exactly the same path on every command.

State appears missing with a custom state root

Repeat the command with the exact --state-root path used at installation. Do not create a new empty state path for an already-managed instance.

A lifecycle operation reports a lock

Confirm whether another manager, upgrade, installer, or updater operation is active. Do not remove a live lock. If no process is active, preserve diagnostics and investigate how the previous operation ended before touching the instance lock.

The styled administrator interface is unhealthy
  1. Open Updates & System if accessible.
  2. Run health check.
  3. Use Restore known-good for configuration damage.
  4. Use Emergency disable when native presentation is needed immediately.
  5. Download sanitized diagnostics before further changes.

If Theme Studio is unavailable, use read-only CLI status/verify, then lifecycle disable after conflicts are resolved.

LevelActionResult
1Save/review draftCorrect unpublished settings without affecting live users.
2Restore revision to draftLoad known settings for review; nothing changes live yet.
3Pause themeBypass Nexus presentation while keeping all workspace data.

FAQ

Frequently asked questions

Is Nexus an official ITFlow project?

No. Nexus is an independent GPL-3.0 integration that packages modified ITFlow templates. ITFlow remains a separate upstream project.

Why can't Nexus support every rolling ITFlow revision?

The supported ITFlow source does not expose native theme hooks or a template override registry. Nexus manages a bounded set of verified files and must test the exact upstream templates it changes.

Does Nexus change the database or permissions?

It changes presentation and managed navigation display. It does not replace ITFlow authentication, database logic, ticket permissions, invoice authorization, or role enforcement.

Can GitHub Pages run a real ITFlow demo?

No. GitHub Pages cannot execute PHP or provide the ITFlow database/backend. The included demo is intentionally a fictional browser-only presentation simulation.

Can I directly edit a managed stylesheet?

Not while retaining conflict-safe verification and lifecycle operations. Local edits are detected as drift. Make the change through Theme Studio or build and validate a new compatibility package.

Does pause uninstall Nexus?

No. Pause bypasses Nexus presentation and retains configuration, revisions, assets, and package state for reactivation.

What should be included in a support issue?

Version, compatible ITFlow revision, exact command/action, exit code, sanitized diagnostics, expected/actual behavior, and reproducible steps. Exclude credentials, databases, configuration secrets, client data, protected state, and private screenshots.

Still blocked?

Open a reproducible issue.

Include sanitized diagnostics and exact steps. Use GitHub Security Advisories instead of a public issue for a suspected vulnerability.
